---

## الرؤية

أن يصبح **DRS NEXORA** أداة المراسلة المشفّرة طرف-لطرف الأولى التي يثق بها
المستخدم العربي: أسرع، أجمل، أوضح — دون أي تنازل عن الخصوصية. كل ميزة
جديدة يجب أن تحافظ على القاعدة الذهبية: **الخادم لا يرى المحتوى أبداً**
(X3DH + Double Ratchet)، وكل ما يُعلَن مُنفّذاً هو مُنفّذ فعلاً ومُختبر.

## أين نحن الآن (صورة صادقة — النسخة التجريبية الأولى)

| القدرة | الحالة | ملاحظات |
|---|---|---|
| تسجيل/دخول بالبريد + تأكيد إلزامي | مُنفّذ + مُتحقق ميدانياً | الإصلاح الحرج (الشاشة الرمادية) مضمّن في v0.1.0 |
| محادثات فردية E2EE كاملة | مُنفّذ + مُتحقق محلياً | X3DH، Double Ratchet، OPK ذرّي، OPK batching |
| مجموعات بمفاتيح مشفّرة | مُنفّذ + مُتحقق محلياً | إدارة مشرفين، طلبات انضمام، روابط دعوة |
| مكالمات 1:1 ومكالمات جماعية (حتى 8) | مُنفّذ، **غير متحقق ميدانياً** | WebRTC mesh؛ سجل المكالمات في DB غير موجود (دين) |
| وسائط كاملة (صورة/فيديو/صوت/ملف حتى 50MB) | مُنفّذ | رفع مشفّر، معاينات، مشغل مدمج، معرض وسائط المحادثة |
| تفاعلات/ردود/تثبيت/تعديل/تمرير + سحب للرد | مُنفّذ | داخل المحادثة |
| رسائل مؤقتة + محفوظة + تصدير محادثة | مُنفّذ | مضمّنة في v0.1.0 — بانتظار التحقق الميداني |
| إشعارات نظام فورية عند التطبيق المقتول | **جزئي** | عميل جاهز؛ `push-dispatch` بانتظار خطوات المالك |
| رسائل البريد (تأكيد/استعادة/دعوة) بهوية التطبيق | **جزئي** | القوالب والموقع جاهزة؛ لصقها في لوحة Supabase على المالك |
| قفل تطبيق بيومتري + جدولة | مُنفّذ + مُتحقق محلياً | 0/60/300 ثانية |
| أجهزة موثوقة وحساب | مُنفّذ | جلسات، حظر مستخدمين، تصدير بيانات |

## القواعد الحاكمة (غير قابلة للتفاوض في كل إصدار)

1. **الصدق أولاً**: FINAL_AUDIT يُحدَّث مع كل إصدار — لا كلمة COMPLETE
   إلا لما نُفّذ وبُني واختُبر وتحقق.
2. **لا تراجع أمني**: أي تغيير في التشفير يتطلب اختبارات وحدة جديدة
   تمر 100% قبل الالتزام.
3. **التوافق الرقاقي**: قاعدة البيانات ورموز الهوية تتقبل الترقية من
   النسخة التجريبية الأولى (v0.1.0) — لا حذف تطبيق أبداً.
4. **اختبار قبل وعد**: `analyze = 0`، `test = 100%`، `format = نظيف`
   ثم البناء، ثم فقط الإعلان.

## الديون المفتوحة (مسجلة بصدق في FINAL_AUDIT)

1. مكالمات جماعية بلا سجل DB (مكالمة حية فقط) — مرحلة v1.0.
2. تعقيد O(n²) في بدء mesh للجماعية — مقبول حتى 8، يُحل مع SFU.
3. الرنين عند التطبيق في المقدمة فقط (بلا full-screen عند المقتول) —
   يُحل مع push-dispatch (مرحلة v0.3).
4. `push-dispatch` وSMTP غير منشورين — خطوات المالك (موثقة خطوة بخطوة).
5. تحقق ميداني للمكالمات غير منجز — مرحلة v0.1.x.
