# SECURITY — DRS NEXORA

## 1. نموذج الثقة
- **الخادم (Supabase)** يخزن: نصوصاً مشفرة، مفاتيح عامة، بيانات توجيه
  (من مع من، أزمنة، أحجام ملفات مشفرة). لا يملك أي سر فك تشفير.
- **الجهاز** يملك: هوية X25519 + توقيع Ed25519 + SPK + OPKs داخل
  flutter_secure_storage (Android Keystore)، وحالة الجلسات مشفرة بـ
  AES-256 داخل sqflite بمفتاح من Keystore.

## 2. بروتوكول الجلسات الثنائية (drs-nexora-e2ee-v1)
1. **X3DH** (تأسيس): DH1=DH(IK_A,SPK_B) · DH2=DH(EK_A,IK_B) ·
   DH3=DH(EK_A,SPK_B) · DH4=DH(EK_A,OPK_B) — SPK موقّعة بـ Ed25519
   (رفض إذا فشل التحقق). SK = HKDF(0xFF×32 ‖ DH1..4).
2. **Double Ratchet**: سلاسل إرسال/استقبال + دندنة DH عند كل تغيير
   اتجاه. مفتاح AES-256 + nonce مشتقان لكل رسالة (KDF_CK).
3. **ضمانات**: Forward secrecy، استرجاع بعد اختراق، حماية إعادة
   (عدادات + مخزن مفاتيح متخطاة محدود 100)، تحمل خارج الترتيب.
4. **AD**: يربط كل نص مشفر بـ (بروتوكول|chatId|جهازي) — لا قابلية نقل.

## 3. المجموعات
- مفتاح مجموعة بإصدار (v1, v2, ...) لكل محادثة.
- عند **أي تغيير عضوية** (إضافة/إزالة/مغادرة): المشرف يولّد إصداراً
  جديداً ويغلّفه لكل **أجهزة الأعضاء الحاليين** فقط عبر X25519 زوجي.
  المغادَر لا يستقبل المفتاح الجديد → لا يستطيع فك الرسائل القادمة.
- الرسالة تحمل الإصدار؛ من لا يملك تغليف الإصدار يرى "رسالة بمفتاح
  غير متوفر".
- **حد موثق**: سرية أمامية للمجموعات أضعف من الثنائية (مفتاح ثابت
  بين التدويرات). التدوير الثنائي الطرفي يغطي الرسائل الخاصة كاملة.

## 4. الخادم وقواعد البيانات (RLS)
- 17 جدولاً مع RLS مفعّلة و51 سياسة (45 جداول + 6 تخزين):
  - الرسائل: قراءة للأعضاء فقط، كتابة بمُرسل=أنا+عضوية، تعديل/حذف
    للمرسل فقط (عمود محدود + trigger `messages_guard`)، حجب الرسائل
    بين المحظورين (دالة `is_blocked_by` في سياسة الإدراج).
  - الإيصالات: يكتب مستخدمها فقط؛ المرسل يقرأ إيصالات رسائله.
  - read_marks: حالة القراءة **الخاصة** — سياسة قراءة ذاتية فقط،
    والكتابة revoked حتى عن الأدوار العامة؛ تُكتب حصراً عبر
    `mark_messages_read` (security definer) وهو نفسه يفرض إعداد
    read_receipts قبل كتابة الإيصال العام `read_at`.
  - presence: RLS بلا سياسات مباشرة — لا يُصل إليه أحد إلا عبر
    `presence_heartbeat()` و`get_presence()` (security definer) اللتين
    تفرضان: مشاركة محادثة + تفعيل show_presence + نافذة نبضة حية.
  - group_key_wraps: كل مستخدم يقرأ تغليفه **فقط**.
  - المحادثات الثنائية: قيد فريد كانوني `unique(user_a,user_b) where
    type='direct'` + RPC ذري — يستحيل قوس A↔B مزدوج رغم السباق.
  - الحسابات: `delete_own_account()` security definer يحذف حساب
    auth.users + كائنات تخزينه.
- التخزين: مسار `media/{chatId}/{userId}/{file}.enc` — القراءة
  بعضوية المحادثة، الكتابة والقراءة بملكية المسار (userId)، والحذف
  للمالك فقط.
- الحماية من الإغراق: trigger يحدد 30 رسالة/دقيقة/مستخدم.
- المحتوى لا يصل الخادم مشفراً فقط؛ بل **لا يُفهرس** — البحث نصي
  محلي على الكاش المشفر محلياً.

## 5. الهوية والتحقق
- رقم أمان (Safety Number): SHA-256 لزوج مفاتيح الهوية كأرقام 60 خانة
  للمقارنة البصرية (شاشة الأمان).
- فحص استمرارية عند كل دخول: المفتاح المحلي = المسجل للجهاز؛ عدم
  التطابق يعني إعادة تسجيل صريحة تُعرض في شاشة الأمان (لا تبديل صامت).

## 6. إدارة الأسرار
- لا يوجد أي `service_role` أو سر إنتاج في المستودع. مفاتيح CI
  (keystore) مشفرة كـ GitHub Actions Secrets.
- ما هو عام بالتصميم: رابط المشروع + المفتاح publishable.
- **قرار موثق**: `nexora-release.jks` + `key.properties`
  + `google-services.json` تُتتبَّع في هذا المستودع **الخاص**
  (رؤية private + صلاحية admin للمالك فقط) — السبب: فقدان keystore
  مع كل إعادة تجهيز بيئة كان يعني توقيعًا مختلفًا وفرض إزالة/تثبيت
  على المستخدم في كل إصدار. المحفظة مخصصة لتوزيع APK مباشر (لا متجر
  Play)؛ وإن رُفع المشروع لاحقًا لمستودع عام فيجب سحبها فورًا
  وإعادة التوقيع بمفتاح جديد محفوظ عند المالك.
- `google-services.json` **عام بالتصميم** (إعدادات عميل Firebase
  العامة: رقم المشروع + مفتاح API مقيّد باسم الحزمة) — مُلزم في
  `android/app/` منذ بداية المشروع. السر الحقيقي للإرسال هو مفتاح حساب
  الخدمة ويبقى في Supabase Secrets فقط، لا في المستودع.

## 7. حدود موثقة (لا تدّعي أكثر مما تفعله)
| الحد | التفصيل |
|---|---|
| إشعارات التطبيق المغلق | تكامل العميل جاهز (مضمّن) — إيصال نهاية-إلى-نهاية يتطلب خطوتي المالك: تطبيق SQL `push_tokens` + نشر `push-dispatch` بمفتاح خدمة (BUILD.md). المحتوى لا يمر عبر FCM إطلاقًا (data-only) |
| المكالمات | STUN دائمًا + TURN اختياري عبر `--dart-define` وقت البناء؛ لا تسجيل مكالمات |
| بيانات وصفية | الخادم يعرف أطراف المحادثات وأزمنتها + نبضات الحضور (المحتوى لا) — كما في أي مراسلة |
| آخر ظهور | لا يُعرض "آخر ظهور" إطلاقًا — الخادم يرد فقط بنبضات حية (≤70 ث) للمشتركين بالمحادثة مع تفعيل الإعداد |
| نسخ احتياطي | لا سحابة للمفاتيح — إعادة تثبيت = هوية جديدة، رسائل الجلسات القديمة عند الأجهزة الأخرى فقط |
| استهلاك OPK المتزامن | **مُغلق** — `FOR UPDATE SKIP LOCKED` + إعادة فحص داخل الـ UPDATE |
